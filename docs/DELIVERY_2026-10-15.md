## Account sync

Account data has a per-user local snapshot and pending payload. Writes are queued before network access, survive an offline reload, and retry on reconnection and at bounded intervals. The server uses a row lock and expected revision; stale revisions return the current row rather than overwriting it. A three-way merge combines independent task/settings/history edits. Explicit local deletions and same-field conflicts prefer the local queued change; unmodified fields keep the remote change. This is a deterministic policy, not collaborative text editing. Tokens are excluded from these payloads. The server rejects a payload for another account.

Verification: regression tests cover independent edits, remote additions, local deletions, revision retry and an account reload while offline followed by reconnection. Live SQL probes verified acceptance of the current revision and refusal of a stale revision in a rolled-back transaction.

## Shared rooms

Rooms now use an authoritative database RPC rather than trusting peer broadcasts. Direct client access to the room table is revoked and RLS is enabled. Invite and membership credentials are hashed; raw membership tokens remain in session storage. Each action verifies admission, expiry and host privileges. Lock rejects new entrants; guests cannot publish timer state or lock/kick; removed members are refused. Messages are bounded and stored for the four-hour room lifetime. Expired records are inaccessible and purged when a new room is created. There is no scheduled purge independent of app traffic. Host failover occurs after a 45-second absence. Clients poll every three seconds; suspended/background tabs can therefore relinquish hosting.

Live SQL tests used the anon role to verify locking, guest privilege denial, message persistence and exclusion after removal. Test transactions were rolled back.

## Google and Outlook

Google uses Identity Services; Microsoft uses authorization code + PKCE with exact-origin/source/state checks. Tokens stay in memory in the current tab and do not enter JSON backups.
