## Service Supabase et droits

Le projet `Pomodoro` était `INACTIVE`. Il a été restauré et son état `ACTIVE_HEALTHY` a été confirmé. Auth répond HTTP 200 ; le test Realtime a confirmé deux clients, deux participants et réception du broadcast.

L'inspection a trouvé une politique permettant la lecture des feedbacks anonymes ainsi que des droits de table inutiles, dont TRUNCATE. Le patch reproductible `supabase/quality_hardening.sql` a été appliqué :

- Feedback : INSERT uniquement pour les clients ; identité déclarée nulle ou égale à l'utilisateur courant.
- État de compte : CRUD réservé au rôle authenticated et isolé par les politiques du propriétaire ; aucun accès anon.
- Fonction d'horodatage : search_path fixé.

Vérifications après correction : lecture anonyme de feedback et user_state → HTTP 401 ; INSERT feedback autorisé ; TRUNCATE authenticated refusé ; UPDATE de compte autorisé sous RLS ; une identité temporaire ne voit que sa ligne. Les transactions de test ont été annulées et zéro utilisateur de test est resté.

Deux advisories restent documentés : [visibilité du schéma user_state pour les utilisateurs connectés](https://supabase.com/docs/guides/database/database-linter?lint=0027_pg_graphql_authenticated_table_exposed), nécessaire à l'interface CRUD et protégée par RLS ; [protection contre les mots de passe compromis](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection) désactivée dans la configuration actuelle. Cela ne signifie pas que les données des autres comptes sont lisibles.

## Limites et critères non cochés

- Lecture réelle Spotify Premium : demande un compte Premium connecté et son consentement ; tests PKCE/callback/rafraîchissement ne remplacent pas cette preuve.
- Connexion personnelle Google/GitHub/email : service et callbacks contrôlés, authentification interactive de l'utilisateur non effectuée.
- Lecture/synchronisation de calendrier, verrou de salle imposé côté serveur, historique social durable, widget natif : travaux déjà différés dans le backlog ; pas présentés comme livrés.
- La synchronisation de compte est last-write-wins ; elle ne constitue pas une résolution de modifications concurrentes ni une file offline.
- La radio et les directs restent des services tiers ; le fallback permet de travailler quand ils sont indisponibles.
